# Relato 2026-10-06 09:00 — plugin CAFFMob Draw (identidade e unificação)

Relato de Leonardo Lima, nas palavras do usuário:

> "o plugin no blender está ativando o antigo Home Builder e o BlenderToMob Separado tudo que era Home Builder deve
> fazer parte do novo plugin dentro dos novos critérios do novo Plugin. / Nome do novo Plugin deve se chamar CAFFMob
> Draw em toda a referencia. [...] Usar o MCP do blender na porta 9876 e instale o plugin de novo, verifique cada uma
> destas inconsistencias."

## Problema P1: o "Home Builder antigo" aparece separado do BlenderToMob

Observações do registrador (verificação ao vivo pelo MCP 9876, após reinstalar o `blendertomob.zip` atual):

- Há **um único add-on** de móveis instalado: a extensão `bl_ext.user_default.blendertomob`. O Home Builder não está
  instalado como add-on à parte nesta máquina.
- O que aparece como "Home Builder antigo" é a interface legada **embutida no próprio plugin**: a barra N tem a aba
  **"Home Builder" com 96 painéis** e a aba **"Blender to Mob" com 9 painéis**; os operadores legados mantêm os
  prefixos `home_builder_*` e textos em inglês ("Wall Commands", "Delete Wall"…). 54 ocorrências do texto
  "Home Builder" nos `.py` do pacote.
- As preferências guardam também uma entrada antiga **`blendertomob`** (add-on fora do sistema de extensões), que
  gera `Add-on not loaded: "blendertomob", cause: No module named 'blendertomob'` ao abrir o Blender.
- Evidência: [mcp-addons-e-abas-n.txt](mcp-addons-e-abas-n.txt).
- **Em aberto:** no computador com Windows, o Home Builder original (add-on separado) também está instalado? Se sim,
  os dois registram os mesmos operadores `home_builder_*` e se atropelam.

## Problema P2: o nome do plugin deve ser "CAFFMob Draw" em toda referência

- Hoje: manifesto `name = "Blender to Mob"`, `id = "blendertomob"`, aba "Blender to Mob", prefixos `btm.`/`BTM_`,
  pasta `blendertomob/`, textos e documentação com "BlenderToMob". É pedido de mudança de identidade (não um
  defeito de comportamento).
- **Em aberto:** o identificador técnico (`id` da extensão, pasta, prefixos `btm.`) também muda, ou só o nome
  exibido? Mudar o `id` faz o Blender tratar como outra extensão (arquivos antigos e preferências).

## Respostas do titular (2026-10-06)

- Closure policy: software local (resolvido quando os testes de regressão passam).
- Erro no Windows: sem informações do erro; Blender 5.2.0; o Home Builder "vem junto na instalação", como aqui.
  Pedido: verificar logs e possível cache que impeça o erro localmente.
- Identidade: mudar tudo (nome exibido e identificador), retirar "Home Builder", um nome só: CAFFMob Draw.
- Módulos: personalizar portas, gavetas, puxadores, materiais e divisões internas; salvar como módulo novo na
  biblioteca; trabalhar com agregados (malha importada vira agregado/folha de porta com barra de abertura; agregado
  preso ao pai, movimento limitado, afastar/afundar com opção de perfurar).
- Severidade: critical para todos (prioridade não informada; P0 assumida pelo registrador).
- Verificação de logs/cache feita pelo registrador: o zip não leva `__pycache__`; não há add-ons legados em
  `scripts/addons` nesta máquina; a raiz do repositório é uma extensão instalável com o código antigo e o mesmo id
  (ver bug "Cópia antiga do plugin na raiz…").
